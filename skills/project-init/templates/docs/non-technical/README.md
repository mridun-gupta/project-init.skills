# docs/non-technical — business & product framing

For PMs, stakeholders, leadership, and clients: **what** {{PROJECT_NAME}} does, **why** it matters, and **where** it's going — without implementation detail. Distinct from `layman/`: that track explains mechanics simply; this one frames value and status.

## What goes here

- `overview.md` — elevator pitch, problem, users, value
- `features.md` — capability list mapped to [../../PRD.md](../../PRD.md) requirement IDs
- `roadmap.md` — milestones and status (ties to TRD §8)
- `glossary-for-stakeholders.md` — business terms, not code terms

## Style rules

- Lead with outcomes ("cuts X from hours to minutes"), not mechanisms.
- Requirement IDs from PRD.md keep features traceable — use them.
- Status badges: `planned` / `in-progress` / `done` — keep honest.
