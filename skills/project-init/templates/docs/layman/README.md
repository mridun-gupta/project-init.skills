# docs/layman — plain-language explanation

{{PROJECT_NAME}} explained like you'd explain it to a smart friend who doesn't code. No jargon without an immediate plain-words translation; analogies welcome.

## What goes here

- `overview.md` — what it is, what it does, why anyone cares (3 short paragraphs max)
- `how-it-works.md` — the moving parts explained with everyday analogies
- `faq.md` — questions a newcomer actually asks
- `terms.md` — jargon → plain English, alphabetical

## Style rules

- Sentences a 15-year-old could follow. If a technical word is unavoidable, define it in parentheses the first time.
- Prefer "like a..." comparisons over definitions.
- No code blocks. Ever. If it needs code, it belongs in `docs/technical/`.
